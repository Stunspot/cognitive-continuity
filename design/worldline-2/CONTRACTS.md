# Worldline 2 contracts
Case: ARC-WORLDLINE-2, revision 1, 2026-09-13. Status: implementation-authoritative under the owner's rebuild instruction; independent review pending. This file binds the new timeline seam. The legacy Worldline v1 project API remains unchanged.

## C1. Canonical occurrence
Cognitive Continuity owns all canonical state in its existing v2 episode ledger. Add optional worldline_event and worldline_policy properties to episode-v2.schema.json; they cannot coexist on one row. No new ledger member or state kind is introduced. Ordinary event rows use the existing message, assertion, decision, tool_action, tool_result, outcome or correction type as appropriate. The payload, rather than the episode type, identifies a native Worldline occurrence.

A worldline_event object has format cd-worldline-event/v2; title (1-180 characters, recognition phrase); kind (1-64 characters, lower-case descriptive category rather than admission taxonomy); disposition (recorded or retracted, with retracted permitted only on explicit correction); occurred_at (timezone-bearing ISO datetime); ended_at (nullable ISO datetime, strictly after occurred_at when present); time_basis (observed, source_reported, inferred or recorded); time_precision (instant, day, range or unknown); sources (1-8 source objects); topics (0-12 distinct strings, each 1-80 characters); related_ids (0-16 distinct episode IDs); supersedes (0 or 1 episode ID). Every field is required, using empty arrays or null where appropriate. Additional properties are forbidden. There is no body, transcript, detailed summary, inferred personality profile, or project requirement. The outer episode ID is the event or revision identifier; recorded_at records capture time, independent of occurred_at. Day precision uses a documented day boundary, not a claim that the event happened at midnight. Range precision requires ended_at. When event time is unknown, use capture/record time only as the index anchor with time_basis=recorded and time_precision=unknown; the UI must label it recorded, occurrence time unknown. This is not a fabricated occurrence timestamp.

A source object has kind (conversation, artifact, repository, url, other), locator (1-2000 characters), label (1-120 characters), and owner (1-120 characters). The source remains with its owner. Capture copies the first locator to the existing outer source.locator and sets outer content to the title; semantic validation verifies those identities. Links are never dereferenced by capture or browse. Sources document why it is reasonable to say the occurrence happened, not that every assertion made within the original conversation was true.

Capture rejects recursive secrets, control characters in locators, URL credentials, and executable schemes such as javascript, data and vbscript before entering a transaction. HTTP(S), absolute local paths and opaque source identifiers remain byte-preserved after this check. Host-specific locators may be preserved without pretending the host supports clickable navigation. The HTML renderer only turns HTTP(S) and absolute local paths into links; other locators remain selectable text unless their host-specific scheme has a separately verified adapter. Ordinary prose sanitization must not rewrite source locators, episode IDs, or revision links. A missing destination affects access to content, not the recorded fact that the event happened.

## C2. Scope and retention
The request scope requires exact user and agent values, neither equal to wildcard. Optional project and thread fields are null or exact strings; null means all permitted projects or threads inside the selected manifest boundary. The runtime first validates user/agent and manifest bounds, then filters rows. A manifest bound to one project or thread narrows an all-scope request automatically and reports that effective boundary; an explicitly incompatible exact request returns scope_denied. The stored legacy project '*' means an unassigned/global facet, not permission to mix users. Timeline displays it as projectless.

Timeline scope is a distinct contract. Do not change eligibility_policy.scope_matches, scope_matches_query, the v1 compiler or generic export defaults to make wildcard mean all. Requesting a particular project selects exact-project events, not global events that merely resemble the task. All-thread browsing is ordinary within the permitted owner boundary.

An event is historically eligible when its row/schema is valid, scope matches, recorded_at is not later than as_of, occurred_at is not later than as_of, sensitivity is allowed, it is not forgotten, and its retention expiry has not passed at current execution time. as_of limits event/record knowledge only; it cannot resurrect currently expired or revoked material. Every page rechecks current retention/privacy eligibility even when the generation is unchanged. A completed event's ended_at and a legacy row's past valid_to do not erase occurrence. Environment-version applicability and current-state supersession cannot hide the historical fact. An explicit source-unreachable marker is surfaced as content availability unavailable for an otherwise eligible event; it is never conflated with forgotten or secret-rejected evidence. No absent external locator is fetched to establish reachability. Future plans stay as assertions that planning occurred; they are not recorded as future events already experienced.

## C3. Capture and persistent control
Library commands are capture_worldline(request, registry_path=None) and set_worldline_policy(request, registry_path=None) in continuity_store_v2.py, sharing existing writable workspace resolution, transaction, generation and receipt mechanisms. The timeline CLI delegates these commands; it does not create an independent persistence engine.

A capture request uses format cd-worldline-capture/v2, request_id, workspace selector descriptor, exact user/agent scope with optional project/thread facets, event payload from C1, source_kind, authority, sensitivity, retention, expires_at, expected_generation, idempotency_key, capture_mode (explicit or routine), and retention_guard (boolean). The command resolves absent stored project to '*' only if the manifest permits it; otherwise it uses the manifest project. It returns the existing governed receipt containing event/revision ID. A capture request with retention_guard=true returns capture_suppressed before a write: current explicit no-retention instructions govern even with a standing ordinary policy. A fresh explicit override of that instruction must be resolved by the caller before sending retention_guard=false.

Routine capture requires the effective persistent mode ordinary and sensitivity ordinary. Capture mode explicit requires current human authorization and can use the explicitly authorized sensitivity subject to existing policy. Persistent off suppresses routine capture; it does not prevent a user from explicitly asking to save a particular occurrence. A caller must not use explicit mode merely to bypass missing standing authority.

A worldline_policy payload has format cd-worldline-policy/v1, mode (ordinary or off), and authority_source (safe locator to the user's directive). It lives on an existing permission episode, has no worldline_event payload, exact user/agent identity, project equal to the manifest project boundary, thread null unless the workspace itself is thread-bound, outer authority user-explicit, and no automatic expiry. The payload is set only through the governed policy command using expected_generation and idempotency_key; its outer content is a short factual control-change label. Its response is a receipt, not an occurrence.

The effective policy is the last committed eligible exact-user/agent policy episode in canonical ledger append order within the workspace's fixed boundary. Wall-clock recorded_at and UUID sort order never decide policy precedence; clock regression or equal timestamps cannot undo the last committed off. Policy rows are excluded from ordinary timeline entries. An off marker has immediate effect on subsequent routine transactions. Routine capture rechecks policy under the transaction lock so a concurrent off command cannot be bypassed. No policy means unconfigured: reads and explicit capture work; routine capture is suppressed. The policy read result distinguishes unconfigured from off. Forgetting any policy revision expands to all policy rows in its exact stored scope, so removing a later off marker cannot resurrect an earlier grant; the resulting absence is unconfigured. Imported policy is never effective merely because an export was imported; import remains quarantine-only and source directives require local reauthorization.

For this owner's currently authorized rebuild, the explicit request to restore a persistent autobiographical index is sufficient authority to configure ordinary local occurrence capture in the applicable installed edition, citing this task. Do not ask for the same permission again. For other customer installations, ordinary mode follows the customer's setup choice or subsequent standing instruction, with one clear setup step and no per-event consent loop. A setup decline/off is durable. Changing a private topic or saying 'do not retain this' suppresses routine capture for that work; it must not silently rewrite standing policy unless the user requested that durable change.

The behavioral capture unit is a coherent encounter or piece of work: exploring a question, making an artifact, revisiting an idea, encountering a useful correction, or ending a substantive topic. Neither task labels nor deliverables are gates. Do not log every message or tool call. Derive a stable caller event identity from the observed host task/session/turn plus a bounded occurrence label; hash it for idempotency. Retrying identical input returns the same receipt; the same key with different input fails with idempotency_conflict. Changed recognition belongs to a correction, not a duplicate capture. Check the returned receipt once; do not demand repeat saves for narration or cosmetic changes.

## C4. Correction and forgetting
A correction is an explicit, source-linked capture with one supersedes ID, outer type correction, and current human authority. The target must be an eligible native Worldline event in the same user, agent, project and thread scope. It must be the current leaf of its revision chain. The new payload is a complete replacement of the recognition metadata; it does not mutate prior bytes. It inherits the target's historical event identity through the root episode ID. Reject absent, forgotten, cross-scope, cyclic, branched or stale-leaf corrections.

A later genuine change of mind is a new occurrence related to the earlier event; it is not a correction of what originally happened. An explicit retraction uses disposition=retracted on a correction. Normal browse/overview exclude retracted families from event totals and report the eligible retraction count; inspect retains a clearly retracted history. Resolve the current canonical revision family and its current privacy/retention envelope before display selection. Never fall back to an older revision because the newest is sensitive, expired, forgotten or retracted. Corrections inherit the target sensitivity and retention controls unless the current human explicitly changes them; cosmetic defaults cannot lower classification. An ordinary root followed by a sensitive correction is withheld as a family from ordinary views. Historical as_of does not bypass current family privacy. Browse normalizes each remaining eligible chain to one event with id=root_episode_id, revision_id=selected_leaf_id, first_recorded_at=root.recorded_at, recorded_at=selected.recorded_at and the selected occurrence metadata. A correction may correct when the event happened; its later recorded_at still remains visible. Inspect by root or revision ID returns the eligible revision chain and provenance. The revision history is not itself a list of new events, and overview counts roots. No correction proves that a remembered outcome actually occurred; source_kind, source links, and asserted/observed origin remain visible.

related_ids expresses associative navigation, not evidence dependence; do not add it to generic derivative closure. On forgetting a family, remove references to it from surviving independent event payloads through the same governed transaction, while preserving those events and their source links. Forget planning expands a selected event or revision to its entire correction family before normal derivative closure, so deleting one correction cannot resurrect a sensitive original. This expansion is exact graph traversal, not semantic guessing. Report severed associative edges in the plan separately from deleted dependent material. A three-event association chain must retain both independent neighbors when its middle family is forgotten. True source_ids/supersedes dependencies retain their existing closure semantics. Tombstones remove worldline_event, scrub worldline_policy if selected, clear source.locator for these rows, and remove identifying topics and retained tags. Retain only the minimal schema-valid forgotten marker and non-content custody fields. HTML/JSON projections under Continuity's projections directory are named derivatives and participate in forgetting. Current unedited generated Worldline HTML is recognized by exact renderer template, typed data marker and source IDs, bound to its direct object identity and byte hash in the plan, included in the authenticated backup, and removed through the existing lifecycle adapter before canonical forget succeeds. Edited/unrecognized derivatives remain on the prior blocked named-custody route. Cleanup interruption reports retained phase evidence and backup for disposition, never successful forget with a retained active view. External exported files remain explicitly named custody boundaries under the existing contract; no remote erasure claim.

## C5. Query and paging
Public library entry point: query_worldline(request, registry_path=None), in worldline_timeline.py. The CLI supports browse, overview, inspect, capture, policy, and render; --request reads exact JSON. Legacy scripts/worldline.py retains its old command semantics. Customer launchers route ordinary timeline requests to the new module.

A query uses format cd-worldline-request/v2; mode browse, overview or inspect; request_id; workspace descriptor; scope from C2; authority; as_of; sensitivity_ceiling; from_time and to_time (nullable ISO datetime, half-open occurred-time window); search (nullable string up to 300 characters); topics (array of exact topic filters, all required); kinds (array, any matching kind); include_legacy (default true); order (asc or desc, default desc); page_size (1-100, default 30); cursor (nullable); event_id (required only for inspect); bucket (day, week or month, default day); display_offset_minutes (integer -840..840, default 0); budget (maximum rendered JSON characters, 2000..100000, default 20000); deadline_ms (100..30000, default 5000). CLI may derive exact user/agent from a manifest containing exact values; it must not invent identity from a wildcard manifest.

Search performs Unicode case-insensitive token matching across title, kind and topics only; every query token must occur. No body retrieval, fuzzy inference, semantic ranking service or source URL search is required. Filter semantics are identical across browse, overview, inspect and render. Titles are not assumed unique. A bounded time window or narrow topic is an attention choice, not authority to exclude projectless history.

Each query reads open_snapshot once, binds physical episode reads to generation_path(root, observed_manifest), and checks the manifest/generation digest. It never mixes logical reads that re-resolve the active generation. Return workspace_id, generation, manifest digest, runtime/schema version, effective scope, coverage counts, requested filters, selected IDs and omission counts without exposing out-of-scope IDs. Compute all candidate/coverage/omission counts only after owner scope gating; do not expose foreign totals through scope_mismatch counts. Query is read-only.

A cursor binds the workspace identity, observed generation, canonical query fingerprint including as_of and all eligibility/filter/order fields, and last selected sort key (occurred_at, root event ID). It may be encoded JSON with an integrity digest; it is input, never authority. A resumed page requires the active generation still equals the cursor generation; otherwise return cursor_stale with restart=true. Do not silently use retained generations because forgetting may since have revoked access. Validate cursor size and shape before decoding and never turn cursor contents into filesystem paths. Stable equal-time ordering is by root ID. Response next_cursor must advance or be null; no infinite empty-page loop.

A successful response uses cd-worldline-view/v2, mode, status, entries, next_cursor, has_more, coverage and provenance. Each entry contains id, revision_id, origin (native or legacy_episode), title, kind, occurred_at, ended_at, time_basis, time_precision, first_recorded_at, recorded_at, scope, topics, sources, related_ids, correction_count and content_availability (unverified or unavailable). No content body. Inspect adds revisions; overview adds bucket/topic/kind counts over the full eligible filtered set, not merely the current page. Counts and buckets distinguish native from legacy records, and report truncation/deadline limits explicitly. Date grouping uses the requested fixed display offset, which is printed; local calendar-window boundaries are computed by the caller and passed as timezone-bearing bounds. No hidden claim to full historical timezone reconstruction.

The byte budget applies to the serialized result; remove complete entries rather than truncate titles, links or IDs. If even one eligible entry cannot fit, return budget_too_small with the required next-entry minimum; never return a nonadvancing success. Deadline expiry returns a typed partial result with partial counts and no continuation cursor whose completeness would be false. Out-of-scope material contributes no identities, facets or per-foreign-scope counts.

## C6. Legacy, export and compatibility
Eligible existing non-control episodes appear immediately as legacy_episode entries. Recognition title is whitespace-normalized legacy content, capped at 180 characters with visible truncation; the body is not returned. The index anchor occurred_at defaults to recorded_at with time_basis=recorded and time_precision=unknown; legacy valid_from is assertion validity and must not be silently treated as event occurrence time. Only an explicit verified source-time adapter may promote a legacy occurrence time. Existing source.locator is retained if safe; absent pointers yield sources=[] and source_link_missing coverage, not an invented destination. Preserve recorded time and label that these are retained episode projections, not complete host conversation history. Empty eligible results mean no retained eligible occurrences, never that nothing happened. Faultline failure_occurrence episodes remain eligible legacy occurrences under timeline privacy rules; their rich nested payload is not copied into the timeline.

Keep generic export defaults and v1 project behavior stable. Add explicit --worldline-timeline export mode to existing continuity_store_v2.py export. This selects native and legacy historical episodes with C2 scope and time semantics, excludes worldline_policy control rows, includes needed native revision ancestors, and returns an ordinary Continuity export bundle with an additive worldline_selection descriptor. Query filtering never copies source content. An exact backup/transfer export still contains source-owned episode rows under the existing export contract; it is not the recognition-only view. Native worldline_event metadata and safe locator fields must survive export byte-for-byte. An explicitly declassified revision can be viewed on its own current eligibility, but a transfer family is omitted if any required ancestor fails execution-time privacy; report revision_ancestry_privacy rather than exporting a denied ancestor or an invalid orphan. Existing generic exports also preserve native event locator fields when such an event is selected. Import accepts the additive payload through the existing checksum validation and quarantine-only path; it does not apply policy or merge canon.

No bulk rewrite or historical transcript backfill is required. v1 workspaces remain read-only and produce explicitly degraded legacy projections. v2 readers before Continuity 0.3.0 are not forward-compatible with new optional fields because their schemas forbid additional properties. Ship consumer updates together and advertise minimum runtime 0.3.0. Do not claim same workspace format means downgrade compatibility. Existing old snapshots remain intact. Rollback disables ordinary capture and retains a capable 0.3 runtime for the evolved store; reverting an older workspace snapshot is a separate governed owner action, not an automatic downgrade step.

## C7. Scrollable artifact and degradation
render produces one standalone, self-contained HTML timeline from the same query semantics, with date groups, compact cards, topic/kind filters over its loaded set, source links, event anchors, coverage banner, and accessible keyboard navigation. No server, network library, CDN, analytics, or local-file fetch loop. It includes a declared bounded number of eligible entries (default 300, maximum 2000 and a file-size guard), visibly reports what was omitted, and points to the CLI query needed for another window rather than implying the static artifact can fetch future pages. The ordinary JSON interface supplies persistent model paging.

HTML embeds data safely using escaped JSON or DOM textContent; a source title must never execute markup or script. URI attributes use the C1 allowlist; absolute local paths are converted by an established path-to-URI routine. Render requires explicit --output (or an explicit request.output); it never writes implicitly. Recommend a governed destination beneath Continuity projections with source event IDs, generation, filters, and generated time. User-chosen external output names an external copy boundary.

Missing or invalid workspace returns a typed no-view result and never initializes a store during reading. Unconfigured/off capture state does not block browsing old events. No provider/host surface means no fake tool invocation or save claim. Portable query material, if offered later, must be explicitly unpersisted; it is not required for the first release. One credible failure recovery may advance the task; repeated support-layer failures are reported at the exact boundary rather than spawning a repair campaign.


## C8. Low-friction CLI defaults
browse and overview require only the desired time/filter when the selected manifest supplies exact user/agent identity; default to the configured selector and never invent an owner from wildcards. Empty filters browse the permitted retained past. capture accepts a compact JSON object or title, source locator and stable event-key plus honest occurrence time and authority. Defaults fill kind=conversation, topics/related_ids/supersedes=[], disposition=recorded, ended_at=null, source_kind=agent, ordinary sensitivity, inherited/default retention, and current policy-bound routine mode. Source kind/label/owner may be supplied or use explicitly documented local defaults; unknown source ownership stays labelled unspecified, never guessed. A current-event flag may use the observed capture instant; an old event never silently receives that time. Before building a correction request, load the target to inherit privacy/retention. The convenience layer reads the current generation and hashes the stable source/event key, while the transaction still handles races. Explicit capture mode requires the caller's actual current authorization; low-friction defaults cannot invent it. Small JSON remains available for precise payloads. Routine use never requires a model to hand-assemble every envelope field.
